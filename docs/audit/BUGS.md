# GameHandler — bugs and reliability findings

**Scope.** Correctness and reliability defects in the Rust workspace at
`d56782d`: logic errors, incorrect state transitions, off-by-one, error paths
that silently swallow failures, resource leaks, races, bad handling of
empty/missing/malformed data, and — the project's own dominant defect class —
**a check that passes without inspecting what it claims**. Security posture is
`SECURITY.md`; advertised-vs-implemented is `FEATURES.md`. This document does
not repeat either.

**Method.** Every finding below is either (a) read directly out of the source
and cited, or (b) reproduced by running something. Where a finding came from a
sub-audit rather than my own reading, I re-checked the citation before
including it. Two claims raised during the audit were **refuted by measurement
and are recorded as refuted** in §"Refuted" rather than quietly dropped; one
premise of the audit brief was also wrong and is recorded in `FEATURES.md` §0.

**Severity.**

| Level | Meaning |
|---|---|
| **P0** | Silent, irreversible data loss, or a failure the user cannot perceive at all |
| **P1** | A user-visible false statement (success reported for a failure), a primary flow unreachable, or a whole-suite check that cannot fail |
| **P2** | A real defect with a bounded or recoverable impact |
| **P3** | Edge case, cosmetic divergence, or a comment/test that describes something the code does not do |

Two findings are worth stating before the table, because they frame it:

- **The port is faithful.** Almost every P2/P3 below is a *faithful copy of the
  reference's own behaviour*, verified against `gamehandler/`. That is a
  correctness property, not an excuse — but it means the fix direction for those
  rows is "deliberately diverge", which is a decision the project has already
  made once (the `B-07` stderr drain) and has the machinery to record.
- **The failure paths are where the divergence is.** The happy paths were ported
  with the reference open; the failure paths were ported from memory of what a
  failure path looks like. `BUG-01` through `BUG-10` are all on that seam — as,
  in the most expensive instance, is `BUG-35`.

| ~~**BUG-11**~~ **WITHDRAWN** | — | **Withdrawn 2026-09-13: false positive; the code is correct.** The claim was that `Vec::dedup` after the sort loses case variants where Python's `set` keeps them, because the sort key (`to_lowercase()`) and the dedup key (`PartialEq`) are different keys. The premise is wrong: the sort's **primary** term *is* the fold, so entries whose folded forms are equal always land adjacent and `dedup` removes exactly what the `set` removes — nothing can sort between two entries that compare equal on the leading term. Re-measured against the reference on a 40-game fixture (ten base categories × spelling/upper/lower/alternating, run through the real `Library.categories`): the reference returns **39** entries and this port returns **39**, the single collapse being `RPG`, whose upper form is itself.
