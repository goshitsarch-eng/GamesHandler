# COSMIC UX audit

Scope: the libcosmic UI of `gamehandler`, judged against COSMIC conventions and
against libcosmic's own idioms — widget choice, spacing and rhythm, theming,
accessibility, interaction conventions, window and chrome behaviour, and
consistency between pages. The subject is `crates/app/src/view/` and
`crates/app/src/main.rs`; the toolkit is read at the pinned rev
`a401af8b1c54a8abd393b8c5b7c8809402f83850`
(`/home/gosh/.cargo/git/checkouts/libcosmic-41009aea1d72760b/a401af8`) and its
vendored `iced`, and every toolkit behaviour claimed below was read from that
tree rather than assumed. The reference for parity is the Python 3 + PySide6/QML
application under `gamehandler/`.

Two classes of finding are recorded here and must be read differently. The first
is defects in this repository. The second is gaps in the pinned toolkit that the
application cannot close on its own; those are marked **toolkit-blocked**, are
still user-visible, and are the ones that need an upstream issue rather than a
patch. Where a finding is the *behavioural* half of a false comment, the comment
itself is filed in `ARCHITECTURE.md` and cross-referenced, so no defect is
counted twice.

It was performed by reading `crates/app/src/view/` at commit `d56782d`. The
reconnaissance pass was read-only; the fixes it produced landed separately on
branch `audit-hardening` and each row below that has one carries a **Status**
tail — one does (`UX-05`).

Nothing in this document was derived from a screenshot. Every claim is a line
read from source, or an arithmetic result reproduced from constants read from
source, per the rule recorded in `docs/audit/BASELINE.md:193-200`.

## Verified sound

Each item below was read and confirmed during this audit, and is cited so it can
be re-checked rather than trusted.

- **Every page is reachable and none is a stub.** `crates/app/src/main.rs:3576-3585` — `#[cfg(test)] const PENDING_PAGES: &[(Page, &str)] = &[];` — with the doc above it at `:3560-3575` recording that the placeholder function itself is gone. All six `view_body` arms dispatch to a real view, and `crates/app/src/main.rs:8879-8906` asserts no body draws a "not ported yet" placeholder.
- **No handler is a silent no-op.** `crates/app/src/main.rs:5450-5671` runs every message through the real dispatcher and asserts that the set with a non-empty effect equals a 61-entry expected list. The only exclusions are named in the filter at `:5456-5467` and both are handled in `App::update` (`:3812-3823`), not dropped.
- **Every `Result`-carrying message reaches a toast.** `crates/app/src/main.rs:2603-2608` (`toast_task`) returns the push task rather than discarding it, and every traced error path in the four flows audited (delete game, install runner, cover fetch, form save) terminates in a rendered toast.
- **The settings that look inert are not.** The 13 default toggles (`crates/app/src/view/settings.rs:68-94`) reach the process through `crates/core/src/runners/launch_opts.rs:624-741`, which sets env or argv for each of the fifteen named options; `close_on_launch` is consumed at `crates/app/src/main.rs:2104`; view mode, sort mode, default runner, close-on-launch, default toggle and colour scheme each validate, write and persist at `crates/app/src/main.rs:1846-1935`.
- **Dropdown-free controls are keyboard-reachable.** The premise that a control without an `Id` is unreachable is false for this toolkit: libcosmic's `Button` passes `operation.focusable(Some(&self.id), ...)` with `id: Id::unique()` by default (`.../a401af8/src/widget/button/widget.rs:359`, `:58`), and `TextInput` likewise (`.../src/widget/text_input/input.rs:853`, `:238`). Tab, Escape and Ctrl+F come from the framework (`.../src/core.rs:139`, `.../src/app/cosmic.rs:672-677`, `:843-852`), and the app composes its own subscription at `crates/app/src/main.rs:3756-3757`. UX-24 is a testability finding, not a reachability one.
- **Disabled controls are genuinely disabled.** The toolkit gates the disabled style on `on_press` being `None` (`.../src/widget/button/widget.rs:443-451`) and marks the a11y node disabled in the same case (`:686-725`). The app uses `on_press_maybe(None)` as a real guard at `crates/app/src/view/installers.rs:543`, `view/plugins.rs:263`, `view/form.rs:833`.
- **All four shortcuts are listed in the UI.** `crates/app/src/shortcuts.rs`'s `shortcut_for` is a pure function dispatched at `crates/app/src/main.rs:3756-3757`; all four appear under "Keyboard shortcuts" at `crates/app/src/view/settings.rs:105-110`, `:178`, rendered `:509-511`, so none is undiscoverable. The module header records its two live-walked divergences honestly.
- **Empty states exist where they can be reached.** Library (`crates/app/src/view/library.rs:333-357`, with a pure decision function and a three-way test at `:875-882`), installers (`view/installers.rs:517-520`), installed runners (`view/runners.rs:414-418`). Only Plugins lacks one (UX-28).
- **No meaning is carried by colour alone.** Runner state is carried by `status_line` strings (`crates/app/src/view/runners.rs:212-219`), cover plates render initials as text (`view/widgets.rs:714-722`), and the runner badge derives its text colour from the theme with a test asserting it differs from its background (`view/badge.rs:92-94`).
- **A launch failure cannot be swallowed by close-on-launch.** `crates/app/src/main.rs:2112-2123` un-hides the window before toasting the failure, and the comment at `:2114-2116` states the reasoning.
- **The destructive actions that do exist are confirmed.** Delete-game and remove-runner both raise a dialog that names its subject and offers Cancel beside a `button::destructive` (`crates/app/src/main.rs:1127-1144`, `:1147-1161`); system Wine draws no remove button at all (`crates/app/src/view/runners.rs:508`, guarded by `row.removable`, false at `:154` against `:161`); clearing filters is reversible and returns its save task. No bulk-delete path exists, so there is no unconfirmed bulk operation to report.
- **Overflow on the vertical axis is reachable.** Each of the seven views was read end to end and none has an early `return` that bypasses its scrollable, so a body taller than the window is always scrollable. The failures in UX-08, UX-09 and UX-21 are all horizontal, which is the axis `scrollable()` does not provide.
- **The inline-dialog rationale is honest.** `crates/app/src/main.rs:1074-1100` states why `popover` was abandoned — `Popover::operate` returns early when `modal && popup.is_some()` (`.../a401af8/src/widget/popover.rs:138-141`), which would make the file's `drawn_strings` instrument photograph an empty tree — and states the cost. UX-06 and UX-07 are the residual cost, recorded rather than hidden.
