# COSMIC UX audit

Scope: the libcosmic UI of `gamehandler`, judged against COSMIC conventions and
against libcosmic's own idioms — widget choice, spacing and rhythm, theming,
accessibility, interaction conventions, window and chrome behaviour, and
consistency between pages. The subject is `crates/app/src/view/` and
`crates/app/src/main.rs`; the toolkit is read at the pinned rev
`a401af8b1c54a8abd393b8c5b7c8809402f83850`
(`/home/gosh/.cargo/git/checkouts/libcosmic-41009aea1d72760b/a401af8`) and its
vendored `iced`, and every toolkit behaviour claimed below was read from that
tree rather than assumed. The reference for parity is the Python 3 + PySide6/QML
application under `gamehandler/`.

Two classes of finding are recorded here and must be read differently. The first
is defects in this repository. The second is gaps in the pinned toolkit that the
application cannot close on its own; those are marked **toolkit-blocked**, are
still user-visible, and are the ones that need an upstream issue rather than a
patch. Where a finding is the *behavioural* half of a false comment, the comment
itself is filed in `ARCHITECTURE.md` and cross-referenced, so no defect is
counted twice.

It was performed by reading `crates/app/src/view/` at commit `d56782d`. The
reconnaissance pass was read-only; the fixes it produced landed separately on
branch `audit-hardening` and each row below that has one carries a **Status**
tail. **Twenty** rows do — seventeen `FIXED`, two `PARTIAL` and one `WITHDRAWN` — and the
pattern that counts them is `PLAN.md`'s own `scripts/plan-counts.py --check`, which
derives the figure from the rows rather than from a sentence beside them.

The figures above were "Eleven ... ten `FIXED` and one `WITHDRAWN`" until `UX-20`
was fixed, and the sentence was already stale before that fix: the count is
twenty, and no commit in this branch updated it. **How far back it had drifted is
not something this reading established**, and it is stated that way rather than
guessed at, because the guess is the defect. What is established is that the
sentence was maintained by hand, that nothing read it back, and that it is the
same failure the paragraph below records — a third time. That is the reason the
numbers here are now the measured ones, and why "count from the rows" is not a
preference.

**This sentence has now been wrong twice, in the same way, and the second time is
worth more than the number.** It first said "one" while four rows carried a tail,
and was rewritten to name the four and to recommend
`grep -c 'Status: FIXED' COSMIC-UX.md` as "the count that cannot drift". That
recommendation is itself the defect class this audit is named for: the sentence
containing the literal string `Status: FIXED` **is a line of this file**, so the
grep counts the advice as a finding and returns one more than the document holds.
A check that passes without inspecting what it claims — here, a check that counts
itself. `plan-counts.py` reads `PLAN.md`'s rows for the same reason `ARCH-05`
records: the number has to come from the rows, not from a sentence about them.

Two of those tails record a **premise** correction rather than a fix. `UX-02`'s
evidence was wrong about which widget the app draws, and wrong in the direction
that understated the gap; `UX-03`'s held as written. Both are noted in place, on
the row, rather than in a footnote a reader of the row would not see — a finding
whose stated reason is wrong is a finding a later reader cannot re-check.

Nothing in this document was derived from a screenshot. Every claim is a line
read from source, or an arithmetic result reproduced from constants read from
source, per the rule recorded in `docs/audit/BASELINE.md:193-200`.
